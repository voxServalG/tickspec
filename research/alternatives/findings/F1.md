# F1: Existing DSLs for Quant Trading Signals & Strategies

> **Research date**: 2026-08-07
> **Scope**: Description languages for trading signals/strategies — NOT full backtesting/execution platforms
> **Note**: Web search unavailable; findings compiled from training knowledge. URLs may need verification.

---

## 1. Pine Script (TradingView)

- **URL**: https://www.tradingview.com/pine-script-docs/
- **What it does**: Both signals AND strategies. Dedicated types: `indicator()` for signals, `strategy()` for strategies with entry/exit/position sizing.
- **Declarative or imperative**: **Imperative** — it's a procedural scripting language with loops, conditionals, mutable variables. However, it has a declarative *feel* for simple cases (e.g., `ta.crossover()` function calls on each bar).
- **Syntax**: Custom language, somewhat Python-like. Runs on a per-bar execution model.
- **Active/maintained**: **Yes, very active** — TradingView's primary scripting language, frequent updates (v5+ as of 2024-2025).
- **License**: **Proprietary/free** — runs only on TradingView platform. Code is visible but not open-source.
- **Key design points**:
  - Type-annotated (v5: `int`, `float`, `bool`, `string`, `color`, `array<>`, `map<>`)
  - Built-in series types for OHLCV data
  - `request.security()` for multi-symbol/multi-timeframe access
  - Libraries for code reuse
  - Can declare inputs as configurable parameters
  - Extremely popular — largest user community of any trading DSL

## 2. EasyLanguage (TradeStation / MultiCharts)

- **URL**: https://www.tradestation.com/ (EasyLanguage); https://www.multicharts.com/ (PowerLanguage variant)
- **What it does**: Both signals and strategies. Has `indicator`, `strategy`, `function`, `paintbar`, `showme` types.
- **Declarative or imperative**: **Imperative** — procedural, event-driven on each bar.
- **Syntax**: Pascal/BASIC-like, very English-readable. Designed for non-programmers.
- **Active/maintained**: **Yes** — still core to TradeStation (est. 1991, one of the oldest trading DSLs). MultiCharts has its variant "PowerLanguage" with extensions.
- **License**: **Proprietary/commercial** — bundled with TradeStation/MultiCharts.
- **Key design points**:
  - Built-in order keywords (`Buy`, `Sell`, `SellShort`, `BuyToCover`)
  - Built-in indicator variables (`Close`, `Open`, `High`, `Low`, `Volume`)
  - Reserved words for cross-bar references (`Close[1]`, `Highest(Close, 10)`)
  - Elaborate signal/strategy distinction with separate execution semantics
  - `.eld` file format for import/export
  - Large library ecosystem (EasyLanguage Vault, TradeStation forums)

---

## 3. MQL4 / MQL5 (MetaTrader 4/5)

- **URL**: https://www.mql5.com/
- **What it does**: Both signals (as custom indicators) and strategies (as Expert Advisors/EAs).
- **Declarative or imperative**: **Imperative** — C-like procedural language. Expert Advisors run event-driven (`OnTick()`, `OnBar()`).
- **Syntax**: C/C++-like with classes (MQL5).
- **Active/maintained**: **Yes** — MQL5 is actively developed. MQL4 is legacy but still widely used. Massive ecosystem.
- **License**: **Proprietary/free** — MetaTrader platform is free to download; language is proprietary.
- **Key design points**:
  - `#property` directives for indicator display settings (declarative metadata)
  - Separate compilation units: `.mq4`/`.mq5` for EAs, `.mq4`/`.mq5` for indicators
  - Built-in trade functions (`OrderSend()`, `OrderClose()`)
  - Event-driven model (`OnInit()`, `OnDeinit()`, `OnTick()`, `OnChartEvent()`)
  - MQL5 marketplace with 10,000+ products
  - Can call DLLs (C/C++)

## 4. NinjaScript (NinjaTrader)

- **URL**: https://ninjatrader.com/support/helpguides/nt8/
- **What it does**: Both signals/indicators and strategies. Separate base classes: `Indicator` and `Strategy`.
- **Declarative or imperative**: **Imperative** — C#-based, fully object-oriented.
- **Syntax**: C# with NinjaTrader-specific attributes and base classes.
- **Active/maintained**: **Yes** — core to NinjaTrader 8 platform.
- **License**: **Proprietary/commercial** — bundled with NinjaTrader.
- **Key design points**:
  - `[NinjaScriptProperty]` attribute for exposed parameters (declarative metadata)
  - `AddPlot()` for indicator rendering
  - `EnterLong()`, `ExitLong()` for trade actions
  - `OnBarUpdate()`, `OnMarketData()` event handlers
  - Can use full .NET ecosystem
  - Strategy Builder (visual/wizard mode) generates NinjaScript code
  - Code generation from visual rules = hybrid declarative/imperative

## 5. ThinkScript (thinkorswim / TD Ameritrade / Charles Schwab)

- **URL**: https://tlc.thinkorswim.com/center/reference/thinkScript
- **What it does**: Signals/indicators primarily. Strategies via thinkBack (limited).
- **Declarative or imperative**: **Mostly declarative** — expression-based, functional-style. More like a formula language than a procedural one.
- **Syntax**: Expression-based, English-readable, similar to spreadsheet formulas.
- **Active/maintained**: **Yes** — still used on thinkorswim platform (now Schwab).
- **License**: **Proprietary/free** — available to thinkorswim account holders.
- **Key design points**:
  - `plot` keyword to declare output series
  - `def` for intermediate calculations
  - Built-in aggregation periods (`AggregationPeriod.DAY`)
  - `AddLabel()`, `AddCloud()`, `AddOrder()` for visual elements
  - Input declarations with defaults
  - Relatively constrained — cannot do arbitrary computation
  - Formula-like nature makes it closer to "declarative" than most trading DSLs

## 6. AFL (AmiBroker Formula Language)

- **URL**: https://www.amibroker.com/guide/afl/
- **What it does**: Both signals and strategies. Used for indicator creation, exploration, and automated trading.
- **Declarative or imperative**: **Imperative** — procedural with array-based operations (vectorized, NumPy-like feel).
- **Syntax**: Custom, somewhat C-like with strong array processing.
- **Active/maintained**: **Yes** — AmiBroker is actively maintained (one-man operation, very fast).
- **License**: **Proprietary/commercial** — AmiBroker license required.
- **Key design points**:
  - Array-first design — operations apply to entire price series
  - `Buy =`, `Sell =`, `Short =`, `Cover =` array assignments for signals
  - `Filter =` for exploration/scanning
  - Built-in optimization framework
  - Formula Editor with real-time AFL reference
  - Very concise for common patterns (`MA = MA(Close, 20);`)
  - `.afl` formula files, `.apx` for projects

## 7. ProRealCode (ProRealTime)

- **URL**: https://www.prorealtime.com/en/prorealcode
- **What it does**: Both indicators and automated trading strategies.
- **Declarative or imperative**: **Imperative** — procedural, BASIC-like.
- **Syntax**: BASIC-like, readable.
- **Active/maintained**: **Yes** — ProRealTime platform (owned by IG Group).
- **License**: **Proprietary/commercial** — bundled with ProRealTime.
- **Key design points**:
  - `indicator` / `strategy` declaration blocks
  - `defparam` for strategy parameters
  - Built-in variables (similar to EasyLanguage)
  - Community code sharing (ProRealCode library)
  - Visual backtesting integration

## 8. JForex API / Dukascopy

- **URL**: https://www.dukascopy.com/wiki/jforex
- **What it does**: Strategies only (Java API for automated trading).
- **Declarative or imperative**: **Imperative** — full Java.
- **Syntax**: Java with Dukascopy JForex API.
- **Active/maintained**: **Yes** — Dukascopy bank platform.
- **License**: **Proprietary/free** — JForex SDK is free.
- **Key design points**:
  - Full Java language, not a DSL — same issue as NinjaScript
  - `@Configurable` annotation for parameter exposure
  - `onTick()`, `onBar()` event handlers
  - More of a framework/API than a language

## 9. QuantConnect Lean (C#/Python)

- **URL**: https://www.quantconnect.com/docs/v2/
- **What it does**: Strategies with signal generation.
- **Declarative or imperative**: **Imperative** — full C# or Python.
- **Syntax**: Standard C#/Python with QuantConnect framework.
- **Active/maintained**: **Yes** — active open-source project.
- **License**: **Open source (Apache 2.0)** — Lean engine is open source.
- **Key design points**:
  - Class-based strategy definition (`QCAlgorithm` subclass)
  - `Initialize()`, `OnData()` lifecycle methods
  - Algorithm Framework (2017+) introduced modular `Alpha`, `Execution`, `Portfolio`, `Risk` models
  - The "Alpha" model is closest to a signal declaration: returns `Insight` objects with direction/magnitude/duration
  - Cloud platform for deployment
  - Not a DSL per se, but the Algorithm Framework pattern is a *de facto* strategy description structure

## 10. StrategyQuant

- **URL**: https://strategyquant.com/
- **What it does**: Strategy generation — builds strategies via genetic programming, outputs code in EasyLanguage/NinjaScript/MQL formats.
- **Declarative or imperative**: **Hybrid** — UI-driven strategy definition, generates imperative code.
- **Syntax**: Proprietary builder interface + exports to other DSLs.
- **Active/maintained**: **Yes** — commercial product.
- **License**: **Proprietary/commercial** — subscription.
- **Key design points**:
  - Strategy Builder with drag-and-drop blocks
  - Genetic algorithm for strategy discovery
  - Export to multiple target platforms (EasyLanguage, MQL, NinjaScript, etc.)
  - Strategy template system — closest thing to a "meta-DSL" for cross-platform strategies
  - SQX file format for strategy definition

---

## 11. Backtrader (Python)

- **URL**: https://www.backtrader.com/ (docs), https://github.com/mementum/backtrader
- **What it does**: Strategy definition + backtesting + live trading.
- **Declarative or imperative**: **Imperative** — Python class-based.
- **Syntax**: Python with backtrader API.
- **Active/maintained**: **Community-maintained** — original author inactive, forks active (backtrader2).
- **License**: **Open source (GPLv3)**.
- **Key design points**:
  - Class-based: inherit from `bt.Strategy`
  - `__init__()` for indicator declaration (closer to declarative)
  - `next()` for bar-by-bar logic (imperative)
  - `cerebro` engine for orchestration
  - Lines abstraction for data series
  - Not a DSL, but popular pattern for strategy definition

## 12. Lean / Zipline / bt (Python backtesting frameworks)

These are not DSLs but define patterns for strategy description:
- **Zipline** (Quantopian): `initialize()` + `handle_data()` lifecycle. Open source (Apache 2.0). Unmaintained (Quantopian shut down 2020), community forks exist.
- **bt** (pmorissette): `bt.algos` module with composable algorithm blocks — more declarative than Zipline.

## 13. Academic / Research Proposals

### 13a. Strategy Description Languages in Research

Limited academic work found specifically proposing a "strategy description language." Most academic work focuses on:
- **Algorithmic trading frameworks** (not language design)
- **Signal processing for finance** (not strategy description)
- **Machine learning for trading** (end-to-end, not declarative description)

### 13b. OMEX / Open Strategy Format

- No widely-adopted open standard for strategy description exists
- The closest concept is **FIX Protocol** for order routing (not strategy description)
- **OpenGamma** and **FINOS** have done work on analytics formats but not strategy DSLs

### 13c. Related: DSLs for Algorithmic Specification (non-trading)

- **PDDL** (Planning Domain Definition Language) — declarative action specification for AI planning; shares some conceptual DNA (preconditions, effects) but designed for robotics/planning, not finance
- **TLA+** / **Alloy** — formal specification languages; could model trading logic but far from practical DSL usage
- **Drools** / **DMN** (Decision Model and Notation) — declarative rule engines used in some financial systems; closer to signal definition but not trading-specific

## Key Observations

1. **No purely declarative trading DSL exists** — all major DSLs are imperative/procedural. ThinkScript is the closest to declarative (expression-based).

2. **All are platform-locked** — every language is tied to its broker/charting platform. There is no widely-adopted platform-neutral strategy description language.

3. **No YAML/JSON strategy format standard** — no widely-adopted declarative, data-format-based strategy description. StrategyQuant's export format is the closest (generates imperative code for multiple platforms).

4. **The "meta-DSL" gap** — despite multi-platform tools like StrategyQuant, there is no open, declarative intermediate representation for trading strategies that could compile to multiple target platforms.

5. **Academic gap** — no significant academic literature proposing a dedicated trading strategy description language. The research community focuses on ML-based signal generation rather than declarative strategy specification.

6. **tickspec's positioning**: If tickspec targets the "declarative signal/strategy description" niche with YAML-based, platform-neutral specification, it would fill an actual gap in the market. The closest existing approach is StrategyQuant's proprietary builder, and there's nothing open-source in this space.
