# F2: YAML/JSON/TOML Configuration-Based Strategy Description Tools in Quant Trading

> Research angle: Open source tools that use YAML/JSON/TOML to describe trading strategies,
> declarative strategy configuration formats, and portable IR output.
>
> **Key question**: Is there anything that does EXACTLY what tickspec does
> (YAML-based, signal/strategy separation, JSON IR output)?

---

## 1. Freqtrade

- **URL**: https://github.com/freqtrade/freqtrade
- **Language**: Python
- **Stars**: ~30k+
- **Strategy description**: Config + Code hybrid. Bot/exchange configuration is JSON (`config.json`), but **strategy logic is pure Python classes** inheriting from `IStrategy`. Users implement `populate_indicators()`, `populate_buy_trend()`, `populate_sell_trend()`.
- **Signal combination**: Signals are combined in Python code — user writes boolean conditions on indicators. No declarative signal weighting or scoring system. The `use_exit_signal` and `ignore_roi_if_entry_signal` flags offer some declarative control, but the core logic is imperative.
- **Portable IR**: None. Strategies are Python code executed within Freqtrade's own backtesting/live engine. No intermediate representation.
- **Relevance to tickspec**: **Low**. JSON is only for config (exchange, pairs, stake). Strategy logic is 100% code. No declarative signal definition, no IR output.

## 2. Jesse

- **URL**: https://github.com/jesse-ai/jesse
- **Language**: Python
- **Stars**: ~5k+
- **Strategy description**: Config + Code. Uses YAML-like configuration for project settings, but **strategies are Python classes** with `should_long()`, `should_short()`, `go_long()`, `go_short()` methods. Indicators are computed in `indicators()` or `generate()`.
- **Signal combination**: User writes imperative Python logic in `should_long()` etc. to combine indicator conditions. No declarative weighting or scoring.
- **Portable IR**: None. Tightly coupled to Jesse's execution engine.
- **Relevance to tickspec**: **Low**. Same pattern as Freqtrade — config is metadata, strategy is code.

## 3. Gekko

- **URL**: https://github.com/askmike/gekko
- **Language**: JavaScript/Node.js
- **Stars**: ~10k+ (archived/unmaintained)
- **Strategy description**: Config + Code. TOML-style config for bot settings, but **strategies are JavaScript plugins** implementing `check()` method that calls `this.advice('long')` or `this.advice('short')`.
- **Signal combination**: Imperative JS logic inside `check()`. No declarative scoring.
- **Portable IR**: None.
- **Relevance to tickspec**: **Low**. Code-based strategies, no declarative format.

## 4. Backtrader

- **URL**: https://github.com/mementum/backtrader
- **Language**: Python
- **Stars**: ~12k+
- **Strategy description**: Pure Code. Strategies are Python classes with `next()` method. Indicators are Python objects composed programmatically. No YAML/JSON strategy config.
- **Signal combination**: Imperative. Users write `if self.data.close[0] > self.sma[0]: self.buy()`. No declarative scoring.
- **Portable IR**: None. Internal Cerebro engine only.
- **Relevance to tickspec**: **None**. Pure code, no config-driven strategy definition.

## 5. Zipline / Zipline-Reloaded

- **URL**: https://github.com/stefan-jansen/zipline-reloaded
- **Language**: Python
- **Stars**: ~4k (reloaded fork)
- **Strategy description**: Pure Code. `initialize()` and `handle_data()` functions. Pipeline API for factor computation.
- **Signal combination**: Programmatic via Pipeline API. Factors can be combined with weights, but it's Python code, not config.
- **Portable IR**: None. Tied to Zipline's simulation engine.
- **Relevance to tickspec**: **None**. Pure Python, no declarative config.

## 6. Lean / QuantConnect

- **URL**: https://github.com/QuantConnect/Lean
- **Language**: C# / Python
- **Stars**: ~9k+
- **Strategy description**: Pure Code. `Initialize()`, `OnData()` methods. Algorithm framework has `Alpha` (signal generation), `PortfolioConstruction` (sizing), `Execution`, `RiskManagement` modules — this is the closest to signal/strategy separation among code-based tools.
- **Signal combination**: Alpha insights have `direction`, `magnitude`, `confidence`, `weight` — similar to tickspec's signal scoring. Portfolio construction modules combine insights declaratively (e.g., `EqualWeightingPortfolioConstructionModel`). But it's all **code**, not config.
- **Portable IR**: None. Proprietary cloud platform.
- **Relevance to tickspec**: **Medium concept, low implementation**. The Alpha/PortfolioConstruction separation mirrors tickspec's signal/strategy split. The insight model (direction + magnitude + confidence) is conceptually similar to tickspec's signal `[-1,1]` range. But it's code-only, no declarative format, no portable IR.

## 7. Hummingbot

- **URL**: https://github.com/hummingbot/hummingbot
- **Language**: Python
- **Stars**: ~8k+
- **Strategy description**: **Pure YAML/Config** (for pure market-making strategies). Hummingbot's V2 strategies introduced a **controller-based architecture** where strategies can be configured via YAML without writing Python code. Templates exist for common patterns (market making, arbitrage, directional trading).
- **Signal combination**: V2 strategies have a `controller` layer that generates signals and a `executor` layer that manages orders. The controller can combine multiple conditions. For market-making, spread/offset are configurable parameters.
- **Portable IR**: None. YAML config is interpreted by Hummingbot's own engine.
- **Relevance to tickspec**: **Medium-High**. Closest to a config-driven strategy format among real projects. The controller/executor split is similar to signal/strategy separation. But: (a) focused on market-making/HFT, not general signal-based trading, (b) YAML configures parameters, not signal logic itself, (c) no portable IR output.

## 8. TradingView Pine Script

- **URL**: https://www.tradingview.com/pine-script-docs/
- **Language**: Pine Script (custom DSL)
- **Stars**: N/A (proprietary platform, open docs)
- **Strategy description**: **Custom DSL**. Pine Script is a domain-specific language for indicators and strategies. Strategies use `strategy()` declaration, `ta.*` functions for indicators, `strategy.entry()`/`strategy.exit()` for orders.
- **Signal combination**: Users can create composite signals using Pine expressions. `plotshape()` for visual signals. Strategy tester shows combined performance.
- **Portable IR**: None. Pine Script compiles to TradingView's internal representation, executed only on TradingView. Not portable.
- **Relevance to tickspec**: **Medium conceptually**. It's a DSL (like .tksp), but it's a general-purpose scripting language, not a declarative config format. No clean signal/strategy separation — everything is in one script. No IR output.

## 9. VectorBT

- **URL**: https://github.com/polaber/vectorbt
- **Language**: Python
- **Stars**: ~3k+
- **Strategy description**: Pure Code (vectorized Python/pandas). Signals are boolean arrays generated from indicator comparisons. `vbt.Portfolio.from_signals()` accepts boolean entry/exit arrays.
- **Signal combination**: Signals are numpy boolean arrays — can be combined with bitwise operators (`&`, `|`) and weighted with `np.where`. The API is clean but imperative.
- **Portable IR**: None. Signals are in-memory arrays.
- **Relevance to tickspec**: **Low-Medium**. The idea of generating signals as data (arrays) and then combining them into a portfolio is conceptually similar to tickspec's pipeline. But it's code-based, not declarative.

## 10. Strateobot / StrategyQuant

- **URL**: https://strategyquant.com/ (commercial)
- **Language**: N/A (commercial product)
- **Strategy description**: **Visual/no-code** strategy builder. Users define conditions via GUI (dropdowns for indicators, operators, thresholds). Can generate MQL (MetaTrader) or EasyLanguage (TradeStation) code.
- **Signal combination**: Declarative via GUI — condition blocks combined with AND/OR, with entry/exit rules. Similar to what tickspec does in YAML.
- **Portable IR**: Outputs code in target languages (MQL, EasyLanguage, etc.), not a generic IR. The generated code is tied to the target platform.
- **Relevance to tickspec**: **Medium-High conceptually**. The condition-block model (indicator + operator + threshold + combine) is very similar to tickspec's approach. But: (a) GUI-based, not text/YAML, (b) outputs platform-specific code, not a portable IR, (c) commercial, not open source.

## 11. MQL4/MQL5 (MetaTrader)

- **URL**: https://www.mql5.com/
- **Language**: MQL (C-like DSL)
- **Strategy description**: Code-based with some declarative elements. Expert Advisors (EAs) are MQL programs. Strategy Tester can optimize numeric parameters. No YAML/JSON strategy definition.
- **Signal combination**: Imperative code. `iMA()`, `iRSI()` etc. called in `OnTick()`.
- **Portable IR**: None. MQL compiles to MetaTrader-specific bytecode.
- **Relevance to tickspec**: **None**. Code-based, platform-locked.

## 12. Catalyst (Enigma)

- **URL**: https://github.com/enigmampc/catalyst
- **Language**: Python
- **Stars**: ~800+ (unmaintained since ~2019)
- **Strategy description**: Fork of Zipline for crypto. Pure Python `initialize()`/`handle_data()`. No YAML/JSON config for strategies.
- **Signal combination**: Imperative Python.
- **Portable IR**: None.
- **Relevance to tickspec**: **None**. Code-based, unmaintained.

## 13. PyAlgoTrade

- **URL**: https://github.com/gbeced/pyalgotrade
- **Language**: Python
- **Stars**: ~3k+
- **Strategy description**: Pure Code. `onBars()` method, imperative signal logic.
- **Portable IR**: None.
- **Relevance to tickspec**: **None**.

## Analysis: Does Anything Do EXACTLY What tickspec Does?

**No.** Nothing found matches tickspec's specific combination of:

1. **YAML as the primary strategy definition language** — not YAML for config + Python/JS for logic. tickspec's `.tksp` files ARE the strategy.

2. **Clean signal/strategy separation** — signals output `[-1,1]`, strategies combine signals into operations. Lean/QuantConnect has a similar architectural split (Alpha/PortfolioConstruction), but it's code-based, not declarative.

3. **Weighted signal combination in config** — signals declare their weight and combine into a composite score declaratively. StrategyQuant does this via GUI, Lean does it via code.

4. **Portable JSON IR output** — tickspec compiles to a canonical JSON IR that could theoretically be consumed by any execution engine. Every other tool either: (a) executes directly in its own engine, or (b) generates platform-specific code (StrategyQuant → MQL).

**The closest partial matches are:**
- **Lean/QuantConnect**: Similar architectural separation (Alpha insights with direction/magnitude/confidence → Portfolio Construction), but code-only, no declarative format, no portable IR.
- **Hummingbot V2**: YAML-based configuration with controller/executor separation, but focused on market-making, YAML configures parameters not signal logic.
- **StrategyQuant**: Condition-block model similar to tickspec's declarative approach, but GUI-based and outputs platform-specific code, not a portable IR.

**tickspec's unique value proposition**: It is the only tool found that combines declarative YAML strategy definition, explicit signal/strategy separation with weighted scoring, and portable JSON IR output — a "compiler for trading strategies" rather than a "trading bot with config."

---

## Implications for tickspec Positioning

1. **No direct competitor** in the "YAML DSL → JSON IR for quant signals" space.
2. **Lean's Alpha model** is the closest conceptual peer — tickspec could position as "declarative Lean Alpha."
3. **Hummingbot's config-driven approach** validates the market desire for code-free strategy definition.
4. **The IR output is the strongest differentiator** — no other tool produces a portable, engine-agnostic intermediate representation.
5. **Pine Script** is the most popular DSL for trading, but it's imperative and platform-locked. tickspec could be positioned as "what if Pine Script was declarative and portable?"
